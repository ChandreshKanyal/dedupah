## Open decisions (ask the user; do not decide alone)

1. Should new portal projects start on **Balanced** instead of Careful? Careful finds about 4 in 10 duplicates, Balanced about 9 in 10 with
   almost no wrong merges (section 104). The command line already defaults to Balanced.
2. **Next phase: integration with Shankar's image engine** (OCR of ID cards, face matching). Only a proposal exists: section 12 of the
   Word overview and docs/RESEARCH_MULTIMODAL.md. Agree the interface with Shankar first.
3. **Engine robustness:** about 5 million records (clustering is pure Python; about 30 GB extrapolated, section 23); a run that dies
   half way; a source that changes shape.
4. Smaller items:
   - a call to match one new record against existing people;
   - end-to-end sweeps of second approval, schedules and database destinations;
   - auto-start of the preview after a reboot;
   - renaming the package before any PyPI release (the name `dedupe` is taken).

## Known gaps

- Email notices were not tried against a real mail server. Users who sign in through single sign-on have no address in the portal.
- Assignments have no due dates and no workload view. Lessons only suggest; they never apply a change.
- The live rule test reads all pairs of the latest run each time. A two-column "similar" rule does not find pairs by itself.
- No transliteration between scripts. No large language model.
- The run dialog still names rule versions in a one-person project.

## How to work on this server (shared EC2 machine)

**Other services:** do not touch other people's services. Shankar's uvicorn is on 127.0.0.1:8000; also leave alone the host PostgreSQL
5432, Superset 8088, gunicorn 8080/8793, Ollama 11434 and Zabbix 10050. Never use the host PostgreSQL. Never open other ports without
asking. Never run `docker compose down -v`: it deletes the database.

**The user's portal:** the `dedupe-preview` container on 127.0.0.1:8001. It mounts `src`, so run `docker restart dedupe-preview` after a
change.

**After a reboot:**
1. `docker compose up -d postgres`;
2. start the preview: the `docker run` command is in the assistant's memory notes, file `ec2-server-constraints`.

**Tests in Docker:**
- `docker build -q --target test -t dedupe-test .`
- run pytest with `src`, `tests` and `configs` mounted. The full suite mounts `src` live, so either do not edit while it runs, or run it
  on a snapshot copy of the three folders.
- ruff: `python -m ruff check src tests` in the same image.
- JavaScript: `node --check` on each changed file.

**Browser checks:** Playwright scripts against the sandbox `sbx-ui`, in `~/agent-review/` on this server (not in the repository).
- Run one with `lib/run_browser.sh sbx-ui <dir> <script>`.
- Reset the sandbox with `lib/reset_sandbox.sh sbx-ui`, and run `docker restart sbx-ui` after every UI change.
- Useful sets: `e2e/` (e1-e4), `redesign/`, `builder/`, `questions/` (q0, then q1 and q2).

**Benchmarks:** `~/agent-review/scoring/bench.py 1200 7` (standard) and `presets.py 1200 7` (ready-made settings).

**UI rules:**
- no gradients, shadows, animation, `::before` or `border-left`;
- light theme only; desktop width;
- no characters above U+2000 except dashes and quotes;
- avoid the global `.check` and `.empty` class names;
- never pass null to `replaceChildren` (use `fill` / `add` / `el`).

**DuckDB** is pinned below version 2.
